# 东方Project BGM播放器（TouhouBGMPlayers）

Windows 平台的东方 Project BGM 播放器。覆盖 **全部官方作品**（TH06–TH20 共 21 部整数正作、7 部黄昏边境格斗作、1 部官方重制版），**运行时直接读取游戏原始数据文件**，不预提取音频资产、不调用外部拆包程序。曲名使用各作原始日文名，循环点以整数样本内嵌。

当前版本：**1.7a**

## 收录作品

- **整数正作及小数点外传（TH06–TH20）**：東方紅魔郷（TH06）、東方妖々夢（TH07）、東方永夜抄（TH08）、東方花映塚（TH09）、東方文花帖（TH09.5）、東方風神録（TH10）、東方地霊殿（TH11）、東方星蓮船（TH12）、ダブルスポイラー（TH12.5）、妖精大戦争（TH12.8）、東方神霊廟（TH13）、東方輝針城（TH14）、弾幕アマノジャク（TH14.3）、東方紺珠伝（TH15）、東方天空璋（TH16）、秘封ナイトメアダイアリー（TH16.5）、東方鬼形獣（TH17）、東方虹龍洞（TH18）、バレットフィリア達の闇市場（TH18.5）、東方獣王園（TH19）、東方錦上京（TH20）
- **黄昏边境格斗作**：東方萃夢想（TH07.5）、東方緋想天（TH10.5）、東方非想天則（TH12.3）、東方心綺楼（TH13.5）、東方深秘録（TH14.5）、東方憑依華（TH15.5）、東方剛欲異聞（TH17.5）
- **官方重制版**：東方紅魔郷: New Classic（TH06NC）

前两类作品在游戏列表里按编号序混排（TH07 → TH07.5 → TH08 …）；官方重制版排在列表末尾。

## 特性

- **直读原始数据**：运行时按内嵌索引从容器取音频。整数作读 `thbgm.dat`（TH06 为 `bgm\th06_NN.wav`），黄昏作读各自容器（Suica / 双层 XOR / TFPK `.pak`），新典读 `data\bgm\th06_NN.opus`（自定义 Opus 容器，非 Ogg / RIFF），内存解出、零落盘；
- **循环折返零磁盘 IO**：整轨驻留内存，intro/loop 按整数样本展开；
- **三种循环模式**：无限循环 / 普通（intro → loop×N → 额外 X 秒 → 淡出 F 秒）/ 随机，参数可调；
- **不循环曲（ED/Staff Roll）**：普通/随机模式播一遍即停（不做淡出），无限模式照常整曲循环，导出时则正常受循环参数影响；
- **TH13 灵界版**：主版 / 灵界版一键切换，交叉淡化无爆音；
- **预读缓存**：切曲基本零等待；
- **音频可视化**：独立的实时可视化窗口 —— A 频谱条（52 根对数频柱）/ B 示波器（上下分屏 L/R）/ C 电平 + J 相位相关 / D 利萨如（带余辉）/ 封面。四块可分别开关；跟随主窗口贴附（顶对齐、等高、只能拖右边缘），**主窗口最大化时自动挤进右侧一列**（曲目表被挤窄，分隔条可拖）；封面按作品显示，主/副版切换时跟着换（素材已固化进程序，主题、性能旋钮见「设置 → 可视化」）；
- **播放列表**：29 部作品列表 + 收藏 + 自定义跨作品列表；框选多选、拖动排序、回车即播；
- **导出 WAV**：按播放时间线渲染（N / X / F 生效），支持批量导出；导出前可选版本（原版 / 灵界版 / 新典 / 原典，按所选曲目的作品开放），导副版时文件名自动加后缀；
- **全局多媒体键**、**输出设备选择**（跟随系统自动流路由 / 指定声卡）；
- **深色主题**、便携运行（设置/收藏/列表都写在 exe 旁，不写 AppData）。

## 运行环境

- Windows 10 1607 或更高
- **[.NET 10 Desktop Runtime](https://dotnet.microsoft.com/download/dotnet/10.0)**（框架依赖部署，程序本体只有几 MB。要装 **Desktop** 版 —— 基础版 .NET Runtime 不含 WPF / Windows Forms，装了起不来）
- 至少一部游戏的原始数据（程序不含任何游戏资产，需自行准备，见下文「版权」）

## 构建

前置：**[.NET 10 SDK](https://dotnet.microsoft.com/download)**（首次构建需联网还原 NuGet 依赖：NAudio 3、VorbisPizza、Concentus）

```
git clone <仓库地址>
cd TouhouBGMPlayers/src
dotnet build -c Release
```

产物在 `src/bin/Release/net10.0-windows/`。把这一层整个拷走即可运行（便携式）。  
Debug 配置把 `-c Release` 去掉即可。

> **构建输入只有 `src/` + `addons/` + `assets/`**。`addons/` 是黄昏作容器解析器（桥接类库，被 csproj 引用）；`assets/icon/bgmplayer.ico` 是程序图标；`assets/cover/embed/*.jpg` 是可视化的封面素材（30 张，长边 512 的 JPEG，约 2.6MB，由 csproj 以通配 `<Resource>` 打进程序集 —— **加图/换图不用改工程文件**）。仓库其余目录与编译无关。

### 自检

```
cd src
dotnet run -- --viz-selftest
```

跑 **39 项**自检（退出码即结果，报告同时写到 exe 旁的 `viz-selftest.txt`）。
覆盖常量与缓冲形状、FFT/RMS/相关度、四个渲染器的离屏像素、余辉状态机、布局比例、
每帧分配、淡出/归零语义、分接节点、节拍退订、延迟取窗、编码路由、放置判定、窗口缩放折算、
设置往返、**封面素材是否齐全**（正向扫 29 个作品 id + 反向枚举程序集里实际打进去的那几张），
以及**整轨波形的算术**（分桶、像素归并、缩放、播放头跟随、文件位置映射、循环入口标记、缓存键、取消）。

> ⚠️ 自检**不覆盖**主窗口布局与任何需要真窗口的行为（自检里 `Show()` 一个窗口会把进程带下去）——
> 所以断言一律落在「决定」或「渲染结果」上。

另有 `--viz [音频路径]`：只起可视化窗口、直接用音频文件当声源（诊断用，不走主窗口与引擎）。

## 使用

首次运行后到 **设置 → 路径** 为每部作品指定目录：

- **整数正作**：指到 `thbgm.dat` 所在的目录，TH06 指到同时包含 `bgm\` 的那一级；
- **黄昏作**：指到游戏根目录（即含对应容器文件的那一级，如 `th105b.dat`、`th135.pak`、`data.cga` 等所在目录），没配置的作品在列表里灰显，配了就能播。
- **官方重制版（新典 TH06NC）**：指到游戏根目录（即含 `data\` 的那一级）；音频在 `data\bgm`（新典编曲）与 `data\bgm2`（原典编曲），用播放列表上的副版按钮切换。

### 可视化

用播放列表行右侧的**「可视化」开关**打开（与「设置 → 可视化」里的总开关是同一个值）。窗口会贴到主窗口右侧；主窗口最大化时自动挤进右侧一列。设置页里还能调：

- **贴附 / 自由**：不贴附时是一个独立窗口，位置尺寸自己拖、自己记；
- **面板开关**：四块 + 封面分别开关（关掉只是不画，位置仍占着，不会让画面跳）；
- **D 余辉层数**（4～20，默认 10）：D 是唯一吃性能的一块，这是**唯一有效的性能旋钮**；
- **延迟对齐**：画面比声音早/晚多少毫秒（默认 100ms，对应共享模式输出缓冲）。

> 诊断：可视化窗口上按 **F12** 显示帧统计叠层（帧距 / 分析 / 绘制 / 节拍自停次数），**R** 复位峰值。

## 目录结构

```
├── src/        WPF 程序本体（csproj 在这层，bin/obj 挂在 src 下；Resources\ 存内嵌索引/名单）
├── addons/     黄昏作容器解析器源码（Suica/Xor/pakReader）+ 桥接工程 addons.csproj + docs\
├── assets/     素材：icon\（程序图标，编译输入）+ cover\（封面原图）+ cover\embed\（归一化后编进程序的那 30 张）
├── docs/       权威数据材料（定稿曲目表 ×7、作品元数据、审计）+ 构建记录
└── tools/      维护脚本（索引再生成链、封面归一化与校验，见下）
```

## 维护脚本（tools/，需 Python 3）

维护期工具，**不参与编译**；用来从权威数据重新生成内嵌索引并校验。

| 脚本                      | 用途                                                         |
| ----------------------- | ---------------------------------------------------------- |
| `csv_to_tracksjson.py`  | 主系列 `tracklist.csv` → 内嵌索引 `src/Resources/tracks.json.gz`  |
| `csv_to_tfjson.py`      | 黄昏作定稿曲表 → 内嵌索引 `src/Resources/tracks.tf.json.gz`（循环点整数样本）  |
| `csv_to_ncjson.py`      | 新典（TH06NC）曲目表 → 内嵌索引 `src/Resources/tracks.nc.json.gz`      |
| `loop_delta.py`         | 各作循环点权威源解析（th075 cue / 105-155 sfl / 175 ini → 整数样本），与索引比对 |
| `build_audit_xlsx.py`   | 生成循环点审计表（逐曲 + 权威比对 + 汇总）                                   |
| `check_src.py`          | 源码静态自检                                                     |
| `extract_game_names.py` | 从各游戏自带 おまけ.txt 提取正式作品名（对照用）                                |
| `normalize_covers.py`   | 封面归一化：原图 → 长边 512 的 JPEG（**只缩不放**），输出到 `assets/cover/embed/`；需 **Pillow** |
| `make_icon.py`          | PNG → 多尺寸 `bgmplayer.ico`                                  |
| `make_musiccmt_resource.py` | 乐评 json → 内嵌资源 `musiccmt.json.gz`（含成对性校验）。⚠️ 乐评数据更新后重跑并提交 |

数据流（构建期物化，权威源留存）：

```
docs/定稿曲表 ──csv_to_*json.py──> src/Resources/tracks*.json.gz（EmbeddedResource，开箱即播）
assets/cover/ 原图 ──normalize_covers.py──> assets/cover/embed/*.jpg（csproj 通配 Resource，编进程序集）
```

> 封面流程补一句：**原图（38.9MB）不进编译**，只有归一化后的 30 张（2.6MB）会被打进程序集 ——
> 所以换图/加图只要把 512 的 JPEG 丢进 `assets/cover/embed/` 重建即可，**不用改工程文件**。
> 归一化脚本对原图**只读**，产物写别处，可以放心重跑。

> 注意：`tools/` 与 `docs/` 属于**维护者本机资料**——重新生成索引依赖它们，但**编译播放不需要**（索引已提交进 `src/Resources/`）。  
> 反正你的游戏文件也不一定是编写人的环境对吧，直接拿来用肯定会报错的因为路径写死了。
