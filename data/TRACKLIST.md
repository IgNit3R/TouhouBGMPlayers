### 2c. th06 特例：无 thbgm.dat / fmt，散装 wav + `.pos`

th06 是本族的例外作：**无 thbgm.dat、无 thbgm.fmt**，BGM 是 `tsa/kouma/bgm/` 下
17 个散装 wav，循环点在 `紅魔郷MD.DAT` 的 `th06_XX.pos`。

`.pos` = 8 字节 = 2×u32 LE，**单位是 44100Hz 样本偏移**
（依据 `release/tsa/kouma/bgm/README.md`，任务 t101）：

- `pos[0]` = 循环起点（intro 结束）、`pos[1]` = 循环终点，循环段 `[pos[0], pos[1])`
- t101 已排除：MIDI tick / MIDI 文件字节偏移 / 小节对齐(88200·176400) / 4B 帧对齐
- 判定依据：① 17/17 满足 `0 < pos[0] < pos[1] ≤ wav帧数`；
  ② th06_02 开头 0.5s 纯静音(RMS=0) 而 pos[0] 处 RMS=8434；
  ③ 重渲染后续播尾首样本逐字节等于 `wav[pos[0]]` 处内容

换算式（已与标准答案 `release/tsa/kouma/bgm/tracklist.csv` 逐首复核 17/17 一致）：

```
header = 文件大小 - nframes*ch*bits/8      # 真实头长，逐个不同 118~166 B
intro  = pos[0] * 4                       # 数据区内字节偏移（不减 44）
total  = pos[1] * 4
loop   = total - intro                    # == (pos[1]-pos[0])*4
循环起点(绝对) = header + intro
```

> **2026-09-04 更正**：旧版用 `pos*4 - 44`，依据是「与 BgmForAll.ini 逐首吻合」。
> 那是循环论证——ini 自己也按标准 44B 头计算。与标准答案比对后确认为
> **系统性偏早 44 字节 = 11 样本 = 0.25 ms**，已改为 `pos*4`。
> 循环段长度不受影响（`loop = (pos[1]-pos[0])*4` 做减法时偏差抵消）。
