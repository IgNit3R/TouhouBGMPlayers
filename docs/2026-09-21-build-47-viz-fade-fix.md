# build-47：淡影期「往小跳变」与相位表初值（两处修复）

日期：2026-09-21
关联：`docs/2026-09-21-build-42-viz-m4.md`（M4 暂停淡影）、`build-46`（上一轮复验修复）

**缘起**：用户自己 build 后报三条：

1. 暂停与未播放时可视化数据没归 0；
2. 播某些曲子（开头有静音）时**相位表从 +1 那边滑过来**；
3. 「我记得是衰减，但**衰减没多久会有一个往小跳变**的感觉」。

**三条症状 → 两个根因**：

| 症状 | 根因 |
| --- | --- |
| ② 相位表从 +1 滑过来、① 未播放时数据不归 0 | `CorrInitial = 0.8f`（相关度初值） |
| ③ 衰减中「往小跳变」 | `OscilloscopeRenderer` 里一句 `f.Active ? td[idx] : 0.0` —— **暂停瞬间把波形直接拍成直线** |

---

## 一、相关度初值 0.8 → 0

```csharp
/// ⚠️ 参照页写的是 var corr = 0.8（起始偏「假定同相」，避免指针从 -1 甩上来），
/// 但那条不能照搬：参照页只在出声时跑，那个初值根本看不见；
/// 而我们的分析器**空闲时也在跑**（窗口一打开就要画一帧静止态），
/// 于是 0.8 会明晃晃停在屏幕上，再慢慢滑向真实值 —— 观感就是「相位表从 +1 那边滑过来」。
private const float CorrInitial = 0f;
```

0 = 指针停在中位，读作「还没测到」—— 这才是"无数据"该有的样子。
**这一改动同时解决了 ①**：未播放时 J 的指针现在停在中位，而不是停在一个假的 +0.8。

⚠️ 注意「滑过来」只在**启动后第一首**看得到：切曲会走 `NotifyTerminated()` → `Reset()`，
那里本来就把 `_corr` 归 0 ✓ 所以之前的旧初值只在**进程刚起来**那一段露馅。

## 二、B 的 `f.Active` 门控：把淡影按成直线

```csharp
double y = f.Active ? td[idx] : 0.0;   // ✗ 旧写法
double y = td[idx];                     // ✓ 现在
```

分析器**已经把 `WaveL/WaveR` 按淡影比例缩放好了**（暂停 ×15%、归零全 0），
渲染器只需照画。旧写法等于把这份处理**又覆盖回 0** —— 于是：

- 暂停那一刻波形**直接拍平**（不是缩到 15%）→ M4 定的「波形 ×15%」对这块面板**完全失效**；
- 观感就是「衰减没多久突然往小跳一下」③。

**为什么 M4 的淡影自检没抓到**：那条断言量的是 `f.WaveL` 的幅度（15% ✓ 帧数据是对的），
**而没量 B 画出来是什么样**。→ 是覆盖缺口，不是逻辑错。

## 三、自检的两处改动（20 / 20 全绿）

### 3.1 相关度断言：改成「收敛后验方向」

旧断言拿的是**第 1 帧的值**：初值 0.8 时算出 0.83，恰好压着 `> 0.75` 的线过 ——
**看着在验方向，其实只是碰巧**。初值一改（0.8 → 0）立刻崩。
改成先跑 12 帧让它收敛，再断言方向（同相为正、反相为负），并把阈值收紧到 `< -0.4`：

```
相关 同相 0.879 / 反相 -0.733        （旧：同相 0.83 / 反相 0.556）
```

### 3.2 新增「B 淡影」专项

```
B 淡影：条带墨迹 1080（直线 600）→ 波形按比例缩了，没被拍平
```

做法：造一帧 `Active=false` 但波形是 0.15 幅度的正弦 → 离屏渲染 → 数**一条竖条带**
（x∈[150,250)，避开左上角 L/R 标签）里的非底色像素，与「全零帧」比。
真被拍平的话两者**恰好相等**（比值 1.0），所以门槛 1.3 就够。

新 helper `InkInStrip`：为什么按**条带**数而不是数全图 —— 左上角有标签、中间有分割线与中线，
那些是常量，会把「波形到底变没变」淹掉。

## 四、教训（值得记住的一条）

> **自检验的是「帧对不对」，不等于「画出来对不对」——渲染器完全可以无视帧。**

M4 的淡影断言在帧数据上是**正确且通过**的，但 B 渲染器把它覆盖掉了。
凡是「分析器算好一个显示量、渲染器照着画」的分工，**断言要落在渲染结果上**，
否则那条链上任何一环私自改判都测不出来。

同类可再排查的：其余渲染器是否也读了 `f.Active`（已核：只有 D 的余辉该读，
它读的是「推不推新层」，**不是**覆盖已算好的量 ✓）。

## 五、待用户复验
