## 过程中的经验（值得记的）

1. **「渐变 / 平滑」必须在采样层面做**。用 8ms 定时器改音量、用 100ms 缓冲区取用，
   两个时间尺度对不上，30ms 的渐变压根落不进缓冲区。
2. **WASAPI 的 100ms 延迟会让 UI 读到的播放位置滞后一个缓冲区**。
   凡是「读位置 → 重建链」的写法都会因此错开最多 100ms，
   交叉淡化两个错开的相同信号就是梳状滤波。就地改参数可以完全绕开。
3. **`FILE_FLAG_SEQUENTIAL_SCAN` 对循环播放是反的**。它除了激进预读，
   还会激进释放读过的页面，导致每次折返都要真读盘。
   循环播放的场景要么不用这个标志，要么干脆把音轨整轨驻留内存。
4. **同样的坑会踩第二次**。`Thickness` 两参的错误在 `PromptDialog` 修过一次，
   在 `ExportDialog` 又犯了一遍 —— 靠静态检查脚本才拦住。
