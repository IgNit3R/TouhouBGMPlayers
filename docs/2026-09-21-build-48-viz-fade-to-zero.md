# build-48：暂停语义的终点改成 0（§2 修订）

日期：2026-09-21
关联：`docs/2026-09-21-build-42-viz-m4.md`（M4 定的 15% 淡影，**本文件取代其 §2.1**）、
`build-47`（同一次实机复验的另两处修复）

**缘起**：用户暂停后截图问「这样是不是正常的」—— 他说：**利萨如图像正常衰减完了，
但频谱、示波器、电平、相位都不是。**

| 项 | 结果 |
| --- | --- |
| `dotnet build` | **成功**，0 警告 / 0 错误（输出到 `.workbuddy/_tmpbuild`，见文末） |
| `--viz-selftest` | **20 / 20 全绿** |

---

## 一、这不是 bug，是方案原文如此 —— 但它有两个真问题

方案 §二 写的是「暂停语义：**衰减成淡影** —— 向「暂停瞬间显示值的 **15%**」收敛后停住」。
所以 A/B/C/J 停在 15% **是照方案执行的**（用户截图里 A 柱约 15% 高、C 读数 `-27.2`
= 暂停前低 20·log₁₀(0.15) = **-16.5dB**、J 指针回到中位附近，都对得上）。

但实机看下来暴露两条：

| # | 问题 | 说明 |
| --- | --- | --- |
| ① | **五块面板两种收尾** | D 的余辉是**按帧递推**的状态（`0.95/帧` 自己烧到零），不受「15%」约束 → 同一次暂停，**D 衰减干净、其余四块停在 15%**。用户一眼就看出这个不一致 |
| ② | **读数会撒谎** | 停在 15% 时 C 显示 `-27.2` —— **明明没有声音，却读出一个存在的声音**。参照页的行为本来就是衰减到 0 |

（② 这条 M4 当时就标出来过：原话是"相关度/读数会跟着变，可能误导"，当时没细究就往下走了。）

---

## 二、用户拍板：**改成就衰减到 0**

| | 旧（15%） | **新** |
| --- | --- | --- |
| 暂停 | 慢慢衰减，**停在 15%** | 慢慢衰减，**走到 0**（约 1 秒） |
| 停止 / 切曲 / 播完 | 立刻归零 | **不变**：立刻归零 |
| 两种语义的差别 | 「终点不同」 | 「**速度不同**」（渐进 vs 立刻） |

**为什么这样反而不丢语义**：差别从「终点不同」变成「速度不同」——
暂停看得见一段淡出过程（约 1 秒），切曲/播完啪一下干净。这比"停在某个中间值"更符合直觉。

---

## 三、实现：顺带做了减法（−1 常量 −4 字段 −1 标志位）

既然目标恒为 0，「**目标比例**」这个量就失去意义了 —— 留着它会让一整块代码变成死代码：

| 删掉 | 为什么它没用了 |
| --- | --- |
| `FadeRatio` 常量 | 比例恒为 0，`基准 × FadeRatio` 恒等于 0 |
| `_fadeBars[52]` + 暂停瞬间的柱高捕获 | 同上：目标不再是"基准的某个比例" |
| `_fadeRmsL/_fadeRmsR/_fadeCorr` | 同上 |
| `_fadeArmed` 标志位 | 「是不是还在淡出」现在由 `_fadeScale > 0` 直接表达，不需要第二个真相源 |

保留的只有 **`_fadeScale`** —— **波形幅度**是唯一需要自己动画的量
（柱高/电平/相关度本身就有跨帧平滑，目标设 0 它们自己会慢慢走）。

对应的三处目标从 `_fadeArmed ? 基准 × FadeRatio : 0f` 简化成 `0f`。

**`IsSettled`** 也跟着简化：不再比对「基准 × 比例」，直接判**各显示量都 ≈0**
（归零态本来就是 0，所以立刻算落定——不需要单独分支）。

## 四、自检：锁三件事（而不是一件事）

```
[ ok ] 暂停衰减到干净 / 终止立刻归零（§2 修订：过程渐进、终点为 0）
       播放中 电平 0.707／柱峰 0.998／波峰 1／相关 0.728；
       暂停首帧 电平 0.65（92%，须 >50% → 是渐进而非瞬间清零）；
       收敛后 电平 0.003／柱峰 0／波峰 0／相关 0（四者都须≈0）；
       收敛于第 66 帧（1.1s，须 <1.5s）；终止 全零=是 ResetRevision 0→1；终止后不再冒出=是
```

| 断言 | 锁的是 |
| --- | --- |
| **暂停首帧是 92%** | 「暂停是**渐进**的」—— 不是瞬间清零（那是终止的语义） |
| **收敛后四者 ≈0** | 新语义的终点 |
| **收敛在 66 帧 / 1.1s < 1.5s** | 跨项约束：衰减必须比节拍的 1.5s 硬上限**先**走完，否则节拍提前退订、画面永远截在"还差一点" |
| **终止立刻全零 + ResetRevision +1 + 之后不再冒出** | 终止那一套没被改坏 |

旧的 `AtFade()`（判"比例落在 10%~22%"）换成了 `NearZero()`。
原来的断言 `pausedRms > 0f`（"淡影**不是**归零"）**翻了过来** —— 那正是本次要改的东西。

## 五、顺带清掉 6 处过时注释

改语义最容易留下的债是**注释还在描述已经不存在的机制**。本轮清了：

- `VizAnalyzer` 里两处提到「淡影基准 / ArmFade / 方案 §2 的 15% 是相对它算的」；
- `OscilloscopeRenderer` 里「暂停 → ×15%」；
- 自检里 `AtFade` 的说明、B 淡影专项的说明（它用一个 0.15 幅度的正弦当样例 —— 现在那只是
  "任意非零幅度"的代表，不再对应某个产品行为，已改写清楚）；
- `VizWindow` 里空格键的说明。

**规矩**：改语义时，把 `grep` 一遍旧数值/旧符号名当收尾步骤，别让注释撒谎。

## 六、待用户复验

1. 暂停 → 五块（A/B/C/D/J）**一致地衰减到干净**，约 1 秒内走完，画面全空。
