## 二、素材：38.9 MB → 2.64 MB

用户把 30 张原图放进了 `bgmplayer/assets/cover/`，**29 个作品 id 全齐**（th06nc 占 2 张），
混合 png/jpg，尺寸 400×400 ~ 1750×1729，**合计 38.9 MB** —— 直接编进程序会让 exe 涨到 40MB+。

归一化（`.workbuddy/tools/normalize_covers.py`，Pillow）：

| 方案 | 体积 |
| --- | --- |
| 原图 | 38.9 MB |
| **JPEG q88 @长边 512** | **2.64 MB**（采用） |
| PNG 无损 @长边 512 | 13.49 MB |

- **只缩不放**（400×400 的几张保持原样）、去掉用不到的 alpha、一律 JPEG。
- 长边 512 的依据：贴附窗口 560 宽时封面块 ≈280px、内嵌列 420 时 ≈208px ⇒ **一倍余量**。
- **原图原地不动**；归一化产物单独放 **`assets/cover/embed/`** —— csproj 只引用后者。

改名（对齐 `<id>` / `<id>_alt`）：`th06nc_NewClassic` → `th06nc`（主版=新典）、
`th06nc_Classic` → `th06nc_alt`（副版=原典）。

## 三、传入方式

**① 固化进程序集** —— 照抄既有图标的模式（`ThbgmPlayer.csproj` 里那条 `<Resource> + <Link>`），
封面用**通配**一条：

```xml
<Resource Include="..\assets\cover\embed\*.jpg">
  <Link>Resources\cover\%(Filename)%(Extension)</Link>
</Resource>
```

以后加图 / 换图**不用改工程文件**，把 512 的 jpg 丢进 `embed/` 重建即可。

**② 读取**（`VizCover`）：`pack://application:,,,/Resources/cover/<id>.jpg`
—— `Resource` 读的是**内存流，不留文件句柄** ✓；`CacheOption=OnLoad` + **`Freeze()`**
（冻结后两处宿主共用同一实例，也才有跨线程资格）。
⚠️ **不设 `DecodePixelWidth`**：素材本身已经归一化到 ≤512，再设一次会把那几张 400px 的**放大**解码，白费内存 —— 这条不改由自检盯（见 §四）。

**③ 传进面板**：新增 `VizSurfaceHost.SetCover(ImageSource?)`，
封面块里 `CoverImage`（`Stretch=Uniform`，**不裁切**）与 `CoverPlaceholder`（原来的虚线占位）**互斥**：有图折叠占位、无图露出占位。

**④ 谁触发**：`MainWindow.UpdateVizCover(gameId)`，三个调用点 ——
- `ShowPlayingPanel`（**换曲** / 光标移回正在播放那行）；
- `Alt_Click`（切主副版）；
- `<c>未播放</c>` 分支（清空 → 退回占位）。

> ⚠️ **刻意与底部那两行文字不同步**：那两行会跟着**光标**走（老问题修过：移回正在播放那行信息回不来），
> 而封面**不跟光标** —— 用户明确「封面跟随的是曲子、跟播放行为走」，所以在列表里点来点去**封面不动**。

**⑤ 后来者补课**：附件窗口与内嵌区域都是**按需新建**的（开关可视化、切最大化），
新造出来的那块封面块只有占位 —— 所以 `MainWindow` 留一个 `_currentCover`，建的时候补一次，
否则要等下一次换曲才显示（暂停时可能永远不换）。

## 四、自检（新增第 21 项）

```
[ ok ] 封面素材（29 个作品 id 全部可解析 / ≤512 / 副版缺则回退）
       可解析 29/29（缺：无）；超 512px：无；带副版 1 个（th06nc 应为 1）；
       程序集里 30 张（预期 30）；有图→占位折叠 / 没图→占位露出（都不需要 Show 窗口）
```

这条链上有三个会**静默失效**的地方 —— 文件没进 `embed/`、csproj 的 `Link` 写歪、id 拼错；
三者都只表现为「某作没封面」，跑起来看不出是哪一个坏，也没人会逐个点 29 首去试。所以：

1. **正向**：29 个 id 全扫，每个都要能解析出图；顺带锁「≤512」与「副版存在才用 / 缺则同一张」；
2. **反向**：**枚举程序集里到底有哪几张** —— `Resource`-build 的项**不在** `ManifestResourceNames`
   里，得读 `<程序集名>.g.resources`（`System.Resources.ResourceReader`）。多一张、少一张、
   名字改错都能当场抓出来。**只验"能解析出来"是不够的**：那只证明某个名字能查到。
3. **界面层**：拿真控件驱动一遍「有图 → 占位折叠 / 没图 → 占位露出」——
   离屏可验，**不需要 `Show` 窗口**。
