## 二、四件事

### 2.1 暂停 → 淡影：收敛到「暂停瞬间显示值的 15%」后停住（§2）

原来是每题都往 **0** 衰减（照参照页）。方案拍板的是 **15%**，所以改成：

| 量 | 怎么收敛 |
| --- | --- |
| 柱高 `Bars[52]` | 捕获暂停瞬间的 52 个柱高，目标 = 基准 × 15%，走原有 attack/release |
| 电平 `RmsL/RmsR` | 同上 |
| 相关度 `Correlation` | 同上（指针缓缓移到接近中位） |
| **波形 `WaveL/WaveR`** | **唯一没有现成平滑可借用的量** → 单独维护一个缩放系数 `_fadeScale` 动画到 0.15 再乘上去 |

⚠️ **一处需要用户确认的解释**：相关度是**带符号的位置量**，「×15%」的落法是「指针回到接近中位」
（`+0.44 → +0.066`，读数也跟着变）。字面上完全按方案执行，但另一种读法是「冻结原值不动」。
两行就能改（`VizAnalyzer.UpdateLevels` 里那一处 target）。实测数据：`相关 0.946 → 0.142`（15%）。

**实现要点**：基准只在「在播 → 不播」的那一帧抓一次（`ArmFade`），而且**必须在 `UpdateSpectrum` 之前**
—— 那一步会改写柱高，抓晚了就抓到已经开始衰减的值（目标越抓越低，淡影会跑没）。

### 2.2 停止 / 切曲 / 播完 → 归零（§2）

「归零」要**清干净、不留淡影**，而 D 的余辉是**渲染器侧**状态，分析器够不着它。
所以给 `VizFrame` 加了一个**独立的** `ResetRevision`（不是复用 `Revision`）：

- `Revision` **每次重算都变** → 分不出「这帧是新数据」与「这帧是归零后的第一帧」；
- `ResetRevision` 只在 `Frame.Clear()` 时 +1 → D 拿它当「立刻清盘」的信号，
  否则余辉会按自己那套慢衰减（约 1 秒）淡出去，那正是「留了一小段残影」。

触发路径：**播完**（`VizDebugFeed.HasEnded` → 窗口调 `Reset()`，只做一次）、
**切曲**（拖入新文件 → `Rebind` → `Reset()`）。两者都实测过（自检里）。

### 2.3 节拍的退订策略与 1.5s 硬上限（§3.5 / R2）

不播了就**自己退订**，绝非常驻空转：

```csharp
internal static bool ShouldStop(bool active, bool settled, double idleSeconds, double idleTimeoutSeconds)
    => !active && (settled || idleSeconds >= idleTimeoutSeconds);
```

抽成纯函数是因为 `CompositionTarget.Rendering` **在自检里根本不触发**（没有渲染循环），
只有纯函数能扫。硬上限是必须的：万一某个量卡在收敛阈值外（浮点异常），不能让帧回调永远跑下去。

**重新起搏由窗口负责**（`SyncPump`）—— 会让画面重新动起来的事件（起播 / 换源 / 取消暂停）
本来就都发生在窗口侧，不需要反向通知。

**同轮加的两处 CPU 让路**（R2 / §8.1#4 要求暂停后 CPU 回落）：
- 不播时**整段跳过 FFT**（目标已由淡影基准决定，拿冻结样本重算纯属白烧）；
- 不播且落定后**退订帧回调**（`IdleStoppedCount` 计数，供举证）。

### 2.4 延迟对齐偏移可配（§2「偏移可配，默认 100ms」）

新增命令行选项 `--viz-delay <ms>` / `--viz-delay=<ms>`（0…1000，超出夹住、非法忽略），
用 `InvariantCulture` 解析。给了就写回 `AppSettings.Viz.LatencyOffsetMs`，下次不带参数也照旧。

**顺带把延迟取窗的索引数学抽成了纯函数** `VizDebugFeed.RingWindow(written, frames, offsetFrames)`：

> **画面上看不出 100ms 的错位** —— 频谱/波形晚几十毫秒，人眼分不出来 ——
> 所以这类「错了也不报警」的算术必须直接扫，不能靠肉眼验。

同时把三种边界一起锁住：正常取窗 / 写指针跨环尾（调用方取模）/ 数据还不够
（**前面留白读静音**，而不是把环里的旧数据当新数据读出来）/ 偏移比已写入还大（一格都不取）/
负偏移（按 0 处理，否则会算出「写到未来」的窗口）。

| --- | --- | --- |
| **空格 = 暂停 / 继续** | 方案没写，为让 #4 可观测而加 | 附件窗口没有标题栏、也不放控件（M0 决策）→ 用按键：既不破坏「窗口里什么都点不到」，又测得了。**接入期该删**，那时暂停由引擎状态驱动 |

前两条我判断属于「方案已经要求、但里程碑表漏了归属」，所以按最小实现补上并在此记档 ——

### 关键设计：换源为什么用 `Rebind` 而不是 `new` 一个分析器

`ResetRevision` 是**跟着帧对象**计数的。换一份新的 `VizFrame` 会让计数从 0 重来，
而 D 记住的是旧值 → 「归零」这个信号**悄悄丢掉**（上一首的余辉留在画面上）。
所以换源只换读侧、复用同一个分析器实例（`Rebind(feed)` → 内部 `Reset()`），最省事也最稳。

## 五、实测（17 / 17 全绿）

```
[ ok ] 暂停淡影 / 停止归零（§2：收敛到基准 15% 后停住；归零清干净）
       播放中 电平 0.707／柱峰 0.998／波峰 1／相关 0.946；
       暂停后 电平 0.109（15%）／柱峰 0.15（15%）／波峰 0.15（15%）／相关 0.142（15%）；
       收敛于第 64 帧（1.07s，须 <1.5s）；
       归零 全零=是 ResetRevision 0→1；归零后不再冒淡影=是

[ ok ] 节拍退订策略（播放中不退订 / 落定即退订 / 1.5s 硬上限）
       上限 1.5s｜播放中·即便判定已落定=继续；刚不播·未落定=继续；刚不播·已落定=退订；
       未落定·差一点到限=继续；未落定·正好到限=退订；未落定·超限=退订

[ ok ] 延迟对齐取窗（偏移 / 数据不足留白 / 偏移过大取不到）
       无偏移=(from 900 head 0 count 100)；偏移50帧=(from 850 head 0 count 100)；
       默认100ms=(from 11494 head 0 count 4096)；数据恰好够=(from 0 head 0 count 100)；
       数据不足→留白=(from 0 head 50 count 50)；偏移比已写入还大=(from 0 head 0 count 0)；
       frames=0=(from 0 head 0 count 0)；负偏移按 0 处理=(from 900 head 0 count 100)
```

四条量的淡影比例**全部精确落在 15%**，收敛 1.07s 也在 1.5s 硬上限之内 ——
这条跨项约束（「淡影必须先于硬上限收敛完」）正是加在同一个用例里的断言，
否则硬上限会先把画面截在「还差一点」的样子上。
