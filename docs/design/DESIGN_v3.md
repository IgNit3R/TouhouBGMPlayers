## 1. 硬约束

1. **完全便携**：一切可写文件只在程序自己的文件夹里，**不写 %APPDATA%、不写注册表**。
   整个文件夹复制即可用。
2. **不做路径扫描/自动探测**：每部作品的路径由用户手动指定，播放器按固定文件名取。
3. **运行时只读原始游戏文件**（`tsa/`），不调用任何已拆包产物。
   拆包产物（`tracklist.csv`、raw wav、`_bgm_report.md`、`release/tsa/*/bgm`）仅用于
   **生成期参考与校验**，不参与运行时。
4. **曲名一律日语原名**，不显示译名。
5. **tf 侧（th105/th123 等）本期不实现**，但数据模型与接口必须留口。

## 2. 目录布局

```
ThbgmPlayer/
  ThbgmPlayer.exe        ← 框架依赖、多文件（不用 PublishSingleFile）
  NAudio.dll 等依赖
  settings.json          ← 路径 / 播放参数 / 最近播放（程序唯一必写文件）
  favorites.json         ← 收藏
  playlists.json         ← 自定义播放列表
  tracks.override.json   ← 可选，曲名/循环点覆盖（手改或由导出模板生成）
  export\                ← 导出音频默认位置
```

内嵌索引 `tracks.json.gz`（14,485 B）编译进 exe 资源，运行时解压到内存。

## 3. 路径设置

> **路径绝不写死，也没有任何默认值或回退。**
> 代码里硬编码的只有三个固定的**文件名 / 子目录名**：`thbgm.dat`、`bgm\`、`紅魔郷MD.DAT`。
> 所有**目录路径**一律来自 `settings.json`，为空即视为「未设置」（灰显、不可播），
> **不做扫描、不做猜测、不用环境变量、不做相对路径回退**。
> th06 那 17 个 wav 的文件名来自内嵌索引，也不是代码硬编码。
> 程序自身目录同样不写死，用 `AppContext.BaseDirectory` 动态取得。

### 3.1 语义：统一为「游戏目录」

| 类别 | 用户指定的目录 | 播放器取用的文件 |
|---|---|---|
| 常规 20 作（th07–th20） | `thbgm.dat` 所在目录 | `D\thbgm.dat`（固定名） |
| **th06 特例** | `bgm` 文件夹所在目录 | `D\bgm\th06_01.wav` … `th06_17.wav`<br>`D\紅魔郷MD.DAT` |

两种情况下指向的都是游戏根目录，心智模型一致。不做扫描，因此
「代号→目录名」映射（`th06→kouma`、`th07→youmu`、`th08→eiya`）**仅作文档参考**，
实现不依赖。

th06 要点：
- 循环点取自 `紅魔郷MD.DAT` 内的 `th06_NN.pos`（2×u32，44100Hz 样本偏移）
- **字节偏移 = `pos * 4`，不减 44**
- 各 wav 头长 118~166 B 不等，按真实头长定位，不能假设 44
- 容错：若 D 下直接有 `th06_01.wav` 而无 `bgm` 子目录，则视 D 为 bgm 目录、上退一级找 MD.DAT

### 3.2 settings.json

```jsonc
{
  "version": 3,
  "paths": {                                   // 空字符串 = 未设置 → 灰显
    "th06": "E:\\GitWorkspace\\thworks\\tsa\\kouma",
    "th13": "D:\\Games\\th13",
    "th20": ""
  },
  "playback": {
    "loopMode": "infinite",                    // infinite | normal | shuffle
    "loopCount": 2,                            // N
    "extraSeconds": 0,                         // X
    "fadeSeconds": 3,                          // F
    "volume": 0.8
  },
  "lastPlayed": { "game": "th13", "index": 2 }
}
```

- 未设置的作品在作品列表里**灰显**并标注「未设置路径」，点击直接弹目录选择
- **校验只在点「应用」时执行**（另：启动时对已配置作品做一次静默校验）
- **记住最近播放的作品 + 曲目**
- 高级覆盖（仅当游戏被改名/打补丁时用）：
  `"pathOverrides": { "th06": { "posArchive": "..." } }`

## 4. 数据层：三层配置

| 层 | 内容 | 位置 |
|---|---|---|
| **L1** 外部覆盖 | `tracks.override.json` | **仅 exe 同目录**（不再查 APPDATA） |
| **L2** 内嵌索引 | `tracks.json.gz` | exe 资源，14,485 B |
| **L3** 运行时校验 | ZWAV 头 + 文件大小 | 每次点「应用」 |

合并规则：以**作品**为粒度，L1 出现的作品覆盖 L2；单曲以 `index` 为键，
**只覆盖写了的字段**；L1 里 L2 没有的作品直接追加（给 tf 留口子）。

### 4.1 索引字段

```jsonc
{
  "game": "th13", "index": 3,
  "file": "th13_02b.wav",
  "title": "死霊の夜桜（霊界トランス）",
  "musicNo": 2,              // 音乐室编号，无则 null
  "source": "tsa",           // tsa | tf —— tf 预留
  "codec": "pcm",            // pcm | wav | ogg —— tf 预留
  "start": 235432128,        // thbgm.dat 内绝对字节偏移（首轨为 16，不加 0x10）
  "intro": 493216,           // intro 段字节数
  "total": 6517248,          // 整轨字节数
  "loop": 6024032,           // = total - intro；**可空**（tf 侧有曲无循环点）
  "rate": 22050, "ch": 2, "bits": 16
}
```

现状：**21 作 / 346 首 / 0 待判**；th13 的 13 首灵界版不单列 → **可见 333 首**。

| TH06 | kouma | 17 | TH12 | th12 | 18 | TH16 | th16 | 18 |
| TH07 | youmu | 20 | TH12.5 | th125 | 7 | TH16.5 | th165 | 8 |
| TH08 | eiya | 21 | TH12.8 | th128 | 10 | TH17 | th17 | 18 |
| TH09 | th09 | 19 | TH13 | th13 | **18** | TH18 | th18 | 18 |

| TH10 | th10 | 18 | TH14.3 | th143 | 10 | TH19 | th19 | 24 |
| TH11 | th11 | 18 | TH15 | th15 | 18 | TH20 | th20 | 19 |

**列表顺序：按音乐室编号（`musicNo`）升序。**

**无编号曲目补号**（接该作最大编号往后加，排在该作末尾）：

| 作品 | 补号 | 曲名 |
|---|---|---|
| TH11 / TH12 / TH13 / TH14 / TH15 / TH16 / TH17 / TH18 | 各补 **18** | プレイヤーズスコア |

| TH20 | **19** | プレイヤーズスコア |

> 全库 17 条 `b.wav` 中只有 13 条是 th13 灵界版，另有 4 首是**正式曲目必须照常列出**：
> `th07_13b` ボーダーオブライフ、`th08_13b` ヴォヤージュ1970、
> `th09_00b` オリエンタルダークフライト、`th07_10_b` 東方妖々夢 ～ Ancient Temple。
> 判定条件 = `game == th13` **且**存在同名主版 **且** `rate == 22050`。

### 4.3 L3 校验

| 对象 | 检查项 | 失败处置 |
|---|---|---|
| 常规 20 作 | `thbgm.dat` 存在；头 16 字节 `ZWAV` + version=1；**BCD 作品号（`byte[9]`/`byte[8]`）与该作代号一致**；文件大小 == `16 + Σ total` | **标黄不阻断**，仍可尝试播放 |
| th06 | `bgm\` 17 个 wav 齐全；`紅魔郷MD.DAT` 存在 | 同上 |

作品号比对用于抓「把 th13 目录指给了 th14」这类手滑。

## 5. 播放模型（定稿）

### 5.1 单曲时间线（普通 / 随机模式）

```
|-- intro ×1 --|-- loop × N --|-- 额外 X 秒（续播 loop 内容）--|-- 淡出 F 秒（额外一段，边播边淡出）--| → 切下一首
```

总时长 = `intro + N × loop + X + F`。抵达终点后**自动切下一首**。

### 5.2 三种模式

| 模式 | 每首自身 | 下一首 |
|---|---|---|
| **无限循环**（默认） | intro×1 + loop 段**无限** | 不自动切（仅手动） |
| **普通** | intro×1 + loop×N + X + F | 按列表顺序；末首 → 回首（列表循环） |
| **随机** | **与普通模式完全相同** | 当前列表内随机 |

说明：
- **随机只改变「下一首是谁」**，每首自身的播法与普通模式一致，不叠加无限循环
- **N / X / F 仅在普通、随机模式生效**；无限循环模式下不生效
- 手动切曲 / 停止时统一走 **30ms 防爆音淡出**，与设置里的 F 无关
- 循环接缝处加极短淡化，消除 seek 回环的咔哒声

### 5.3 播放列表体系

- **每部作品一张独立列表**（21 张）+ **收藏** + 若干**自定义列表**
- 自定义列表允许**跨作品**混排
- 列表项统一存 **`(game, index)` 二元组**，**不存文件路径** —— 改路径后列表依然有效
- 自定义列表存 `playlists.json`，收藏存 `favorites.json`（均程序目录）
- 列表的**切换**用窗口上的下拉框（分组：作品 / 收藏 / 我的列表）；
  **管理**用顶部「播放列表」菜单（见 §5.4）

### 5.4 UI 布局（定稿）

**自上而下五段，不做侧栏**：

```

│ 设置(S)   播放列表(L)   帮助(H)                 ← 菜单栏  │
├──────────────────────────────────────────────────────────┤
│ 播放列表  [ TH13                     ▾ ]      ← 列表选择 │
├──────────────┬──────┬────────────────────────────────────┤
│ 作品  │ 曲序 │ 曲名                            ← 可拖列宽 │
│ TH13  │ 01   │ 欲深き霊魂                        (不排序) │
│ TH13  │ 02   │ 死霊の夜桜                                 │
│ ...                                                       │
├──────────────────────────────────────────────────────────┤
│  ──────────●───────────────────  01:23 / 04:31  ← 进度条 │
│  [前] [播放/暂停] [次]  循环[无限 ▾] [收藏]  音量 ───●──  │
├──────────────────────────────────────────────────────────┤
```

- **窗口**：默认 **1040 × 720**，最小 **860 × 600**，允许缩放；尺寸与位置存 `settings.json`
- **曲目格式**：`[作品代号] - [曲序] - [曲名]`，代号一律 `THxx`
- **曲目表三列**（作品 / 曲序 / 曲名），**列宽可调**，**不允许排序**
- **进度条在播放按钮上方**
- 未设置路径的作品在下拉框里**灰显**

**顶部菜单**（无「文件」菜单，设置放最前）：

## 6. th13 灵界版切换

- th13 共 **31 条**记录：17 主版（44100Hz）+ 13 灵界版（22050Hz，`file` 后缀 `b`）
  + 1 玩家分数曲（`th128_08.wav`，复用 th12.8）
- **配对天然存在**：`th13_01.wav` ↔ `th13_01b.wav`，按 file 名配对，无需新增字段
- **13 组主版/灵界版时长完全一致**（`total_sec`、`loop_sec` 逐条 Δ=0.00%）
  → 切换可**按秒 1:1 对齐**，播到第 45.3 秒切过去就从 45.3 秒接上，位置不跳
- 实现：同一 dat 开**两条流**，切时约 20ms 交叉淡化；灵界版先重采样到 44100 再混
- **灵界版不单列在曲目表**；播放面板加切换按钮
- 切换后**列表行曲名不变**，仅按钮**高亮**
- **无灵界版的 5 首按钮灰显**：`th13_00` 欲深き霊魂、`th13_17` 聖徳伝説、
  `th13_18` 神社の新しい風、`th13_19` デザイアドリーム、`th128_08` プレイヤーズスコア

## 7. 音频管线

- **WASAPI 共享模式**（系统重采样到设备采样率）
- 跨作品播放 → 播放核心是**多源调度器**，不是「开一个 dat 播到完」。
  切到别作时开新 dat 句柄、释放上一个（毫秒级）
- 采样率混杂（44100 / 22050）→ 管线挂**统一重采样**（NAudio `WdlResamplingSampleProvider`
  或 MediaFoundationResampler）到设备采样率
- 源抽象（tf 侧的口子就在这里）：

```csharp
interface IAudioSource : IDisposable {
    WaveFormat Format { get; }
    long IntroBytes { get; }      // intro 段长度
    long LoopBytes { get; }       // 可空：tf 侧有曲无循环点
    int   Read(byte[] buffer, int offset, int count);
    void  SeekToStart();          // 回到 start
    void  SeekToLoop();           // 回到 start + intro
}
// 现有实现：ZwavSource（thbgm.dat）、Th06WavSource（散装 wav + .pos）
// 未来实现：TfpkSource、OggSource（tf 侧）
```

## 8. 导出音频

### 8.1 参数模型

- 导出参数（N / X / F）**默认沿用播放参数**，但**一旦修改即独立保存**，
  **反向不影响播放参数**
- 实现用「**null = 跟随 / 有值 = 覆盖**」：三个字段各自独立。
  `null` 时实时取播放参数的值；有值则固定，之后播放参数再变也不跟着变
- 导出**一律按「普通模式」的时间线**，与当前处于哪种循环模式无关
  （无限循环没有终点，导出设置里的 N / X / F 就是终点）

### 8.2 两个入口

| 入口 | 行为 |
|---|---|
| **导出…**（右键 / 设置） | 打开对话框，可临时改 N / X / F、选输出路径；**th13 可选版本**（主版 / 灵界版） |
| **快速导出**（右键） | 不弹窗，用当前导出设置直接出文件；th13 取**当前正在播放的版本** |

### 8.3 输出

- 时间线 = `intro + N × loop + X + F`
- 默认格式：**16bit PCM wav，沿用源采样率**（44100；灵界版 22050）
- 默认位置：程序目录下 `export\`
- 默认命名：`{作品代号}_{曲号}_{曲名}.wav`，Windows 非法字符替换为 `_`
  （例：`TH13_16_小さな欲望の星空.wav`）
- 多选可**批量导出**

## 9. 实现红线

| 禁止 | 原因 |
|---|---|
| `Environment.SpecialFolder.ApplicationData` / `LocalApplicationData` | 会落盘 AppData |
| `Properties.Settings.Default` | user.config 写 AppData\Local |
| `IsolatedStorageFile` | 同样落 AppData |
| 写注册表 | 违反便携 |
| `PublishSingleFile` | 会自解压到临时目录；用框架依赖多文件 |

取程序目录统一用 `AppContext.BaseDirectory`。
**只读目录降级**：程序目录不可写（如放进 `Program Files`）时不崩溃，
转「只读模式」——设置仅内存生效、退出即失，标题栏提示。

**授权**：`tools/go-brightmoon` 无 LICENSE，其解密代码**不可移植**进播放器；
但**调用现成二进制无授权问题**。故「从原始 dat 重新扫描」按钮以**外部进程**调用
`brightmoon.exe` / `thdat.exe`。thtk 为 BSD 风格，可放心参考。

### 13.2 `_extract/` 只需保留三类文件

`_extract/` 是 brightmoon/thdat **整包解开的全部游戏资源**（anm / ecl / rpy 等，
每作 200+ 文件，合计 **2.9 GB**），但**生成器只读其中三类**：

- `thbgm.fmt` —— 20 作各 1 个，329~1629 B，合计约 17 KB
- `musiccmt.txt` —— 21 作各 1 个，1.7~7.4 KB，合计约 95 KB
- `_extract/th06/` —— 整个目录保留（`md.dat`、`*.pos`、`musiccmt.txt`，共 1.5 MB）

**其余全部可删**（约 2.9 GB）。清理后 `gen_tracklist_v2.py` 仍可正常重跑。
