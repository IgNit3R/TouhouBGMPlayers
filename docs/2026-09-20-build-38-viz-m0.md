## 四、踩到的坑：XAML 注释里的 `--`（MC3000）

首次 build 失败：

```
src\App.xaml(7,6): error MC3000: An XML comment cannot contain '--',
                              and '-' cannot be the last character.
```

**原因**：新加的注释里写了 `（--viz / --viz-selftest / 无参开主窗口）`。XML 注释体不允许出现 `--`，也不允许以 `-` 结尾——**命令行开关名是重灾区**。改成中文描述后通过。

**对策（已固化）**：`.workbuddy/tools/check_xaml.py` —— 把 `src/**/*.xaml` 逐个当 XML 解析并打印错误行号。
本次 5 个 xaml 全部良构。**改完 xaml 先跑它，别把这个错误留到 build 那一刻。**

> 注意：MC3000 属标记编译阶段，它一报，C# 编译根本没跑到 —— 所以第一次失败时 C# 侧仍是「未验证」状态。

## 五、一处对方案的更正（`ShutdownMode`）

方案初稿（`docs/2026-09-20-plan-visualization-module.md`）曾建议「顺手把 `ShutdownMode` 设为 `OnMainWindowClose`」。**该建议错误，未采纳。**

`--viz` 路径下没有主窗口，改成 `OnMainWindowClose` 会让进程**永不退出**。
最终做法：**保持默认 `OnLastWindowClose`** —— 隔离期只有 1 个窗口 → 关闭即退出（已实测）；
接入期给附件窗口设 `Owner`（天然「随属主关闭」）才是根治点。见已批准方案 §7-R1。

## 八、修订：窗口去标题栏（同日追加）

**来源**：用户 2026-09-20 反馈 —— 「窗口外框应该没有标题栏这种东西」。

**理由**：附件窗口是主窗口的附属物，位置与尺寸都由宿主算出来，标题栏纯属多余；
而且贴附要求与宿主**等高**，多一条标题栏就等于少约 30px 画面。

**做法**（`src/Viz/VizWindow.xaml`）：

| 项 | 值 | 作用 |
| --- | --- | --- |
| `WindowStyle` | `None` | 去掉系统非客户区 |
| `ResizeMode` | `CanResize` | 保留边缘缩放能力 |
| `WindowChrome.CaptionHeight` | `0` | 没有可拖拽的标题区 |
| `WindowChrome.ResizeBorderThickness` | `6` | 边缘缩放热区 |
| `WindowChrome.GlassFrameThickness` | `0` | 不要 Aero 玻璃边框 |
| `WindowChrome.UseAeroCaptionButtons` | `False` | 不要系统那三个按钮 |

**刻意不用 `AllowsTransparency`**：它会让窗口失去任务栏项与 Alt+Tab，而且 airspace 问题一堆。

**连带改动**

- 根元素包一层 `Border`（`BorderThickness=1`，`BorderBrush=Border`）—— 去标题栏后这是唯一的窗口边界，
  否则画面直接贴在桌面上、没有边。
- 拖动改由内容区接管：根 Border 的 `MouseLeftButtonDown` → `Root_MouseLeftButtonDown` → `DragMove()`。
  边缘缩放走 WindowChrome 的 `WM_NCHITTEST`，不进这条路，两者不冲突。整块画布都能拖（里面没有可点控件，不会误触）。
- 新增 `VizWindow.AttachedMode`（默认 `false`）：贴附模式下位置由宿主算，拖动必须关掉，否则与宿主定位互相打架。
  **刻意不从 `AppSettings.Viz.Attached` 初始化** —— 隔离期没有主体，就算设置里勾了「贴附」也得按自由窗口处理，
  否则会得到一个既拖不动、又没人给它算位置的死窗口。判定归宿主，窗口只认这个开关。
- 关窗口靠 Alt+F4 / 任务栏；接入期由宿主管生命周期，**不做窗口内关闭按钮**。
- 任务栏项暂留（`ShowInTaskbar` 默认 `True`）—— 隔离期要靠它找到窗口，接入期再关。
