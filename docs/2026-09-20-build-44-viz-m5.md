## 二、M5 的核心：把「决定」做成纯数据

方案 §九 M5 的验收是「模拟最大化 → 窗口按预期 `Hide()`」。但直接验这个**做不到**：

> 自检**起不了窗口**（`ShutdownMode=OnLastWindowClose`，`Show()` 一个就把进程带下去），
> 而**未 Show 的窗口 `IsVisible` 恒为 `false`** ——
> 「它应该隐藏」这条断言会**永远通过**，等于没验。

所以把决定做成**纯数据** `VizWindowAction`，自测断言的是**「决定让它隐藏」**，不是「它现在隐藏着」：

```csharp
public readonly record struct VizWindowAction(
    VizPlacementMode Mode,
    bool Show, bool Hide, bool SetBounds,
    double Left, double Top, double Width, double Height,
    bool Attached, bool Degraded);
```

`VizPlacementLogic.Decide(host, desiredWidth, embedWhenMaximized)` 按判定结果产出动作：

| 输入 | 动作 |
| --- | --- |
| `Free`（自由模式） | 不动几何、不动显隐，只保证 `Attached=false`（拖动与缩放回到自由窗口那套） |
| `AttachedNormal` | 写几何 + `Show`（宿主从最大化还原回来时，窗口得回来） |
| `AttachedEmbedded` / `Minimized` | **`Hide`** |
| **兜底**（几何 `NaN` / 退化） | **什么都不动，保持可见**（`Degraded=true`） |

窗口侧只剩一层薄胶水：

```csharp
private void ApplyPlacement(VizWindowAction a)
{
    AttachedMode = a.Attached;                       // 先开关贴附（它连带改缩放钩子的策略）
    if (a.SetBounds) { Left = a.Left; Top = a.Top; Width = a.Width; Height = a.Height; }
    if (a.Hide) { if (IsVisible) Hide(); }
    else if (a.Show && !IsVisible) Show();
}
```

⚠️ **兜底分支不是假想**：**未 Show 的 WPF 窗口 `Left/Top` 就是 `NaN`**，
而宿主（主窗口）刚建好就可能被读一次 —— 那是很正常的时序。
往窗口里写 NaN 的后果是窗口直接消失或位置错乱，所以宁可位置不完美、也不要写。

## 三、⚠️ 本轮最隐蔽的一处连带影响：**几何所有权**

`ApplyPlacement` 会写窗口的 `Left/Top/Width/Height`。而 `VizWindow_Closing` 原本**无条件回写**
这几个值到 `settings.json` —— 于是：

> 贴附运行时几何是**宿主算出来的**，一回写就把**用户自己记下的自由窗口位置覆盖掉**。
> 下次他在自由模式下打开，窗口会跑到上一任宿主旁边。

所以新增了判据，并抽成纯函数（散在 `Closing` 里就只能靠读代码）：

```csharp
/// 贴附时不写（几何属于宿主）；没 Show 过也不写（那时是"期望值"不是"实际值"）。
public static bool ShouldPersistGeometry(bool wasShown, bool attached) => wasShown && !attached;
```

对应的：**`Host` 置 null（解除贴附）时调 `RestoreGeometry()`** ——
窗口回到用户自己记下的位置与尺寸，而不是留在"看起来贴过"的地方。

## 四、窗口侧接线

| 成员 | 作用 |
| --- | --- |
| `Host`（可写属性） | 注入宿主。**隔离期恒为 null → 整条贴附路径不跑**，与 M0～M4 行为完全一致 |
| `Host` 的 setter | 换宿主时先退订旧的 `Changed`；置 null 时 `AttachedMode=false` + `RestoreGeometry()` |
| `OnHostChanged` → `RefreshPlacement()` | 宿主移动/缩放/最大化/最小化时重算一次 |
| `RefreshPlacement()` | `Decide(...)` + `ApplyPlacement(...)`；期望宽度取自 `AppSettings.Viz.Width` |
| `Closing` | 摘宿主订阅（窗口都要关了，再有人推 `Changed` 就是白发一次重算） |

## 六、踩到的坑

**`VizWindowAction` 一开始声明成了 `VizPlacementLogic` 的嵌套类型** → 外部引用不到：

```
error CS0246: 未能找到类型或命名空间名"VizWindowAction"
```

C# **不会**把嵌套类型带进作用域（要么 `VizPlacementLogic.VizWindowAction`，要么挪出去）。
**把它挪到命名空间层级、与 `VizPlacement` 并列** —— 它本来就是个对外可见的返回值类型，
不是实现的内部细节。（`BarLayout` 嵌套在 `LevelPhaseRenderer` 里没事，是因为只有它自己用。）
