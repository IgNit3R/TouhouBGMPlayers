## 一、一句话现状

主窗口播放列表行有个**「可视化」开关**（与设置页总开关同一个值）。打开后出现一个
**五块面板**的附件窗口，贴在主窗口右侧、顶对齐、等高；**主窗口最大化时画面搬进主窗口**
（曲目表被挤窄，分隔条可拖调宽窄）；数据来自播放引擎的**分接节点**（音量之后、16bit 转换之前）。

- 入口：主窗口快速开关、设置页「可视化」页、设置菜单「可视化…」、`--viz`（隔离期诊断入口）
- 自检：`dotnet run -- --viz-selftest`（**33 项**，退出码即结果；报告落 exe 旁 `viz-selftest.txt`）
- 代码：`src/Viz/` **6850 行**（含两个自检文件）
- 素材：`assets/cover/embed/` **30 张封面（2.64 MB）**，固化进程序集（见 build-51）

## 三、代码地图（`src/Viz/`）

| 文件 | 职责 |
| --- | --- |
| `VizFrame` / `VizAnalyzer` | 一帧的数据容器 / FFT·峰值·RMS·相关度（+ 淡出归零、60Hz 限频、`Revision` 契约） |
| `IVizFeed` / `VizTap` / `VizRing` | 读侧接口 / **引擎分接节点**（透传 + 写环，「活动性即播放状态」）/ 单写单读环 |
| `VizPump` | 节拍（跟 vsync、自我退订）+ **帧距/耗时统计** |
| `VizPanel` / `VizStyle` / `IVizRenderer` | 自绘面板 / 主题取值 / 渲染器接口 |
| `Renderers/` | A 频谱条 / B 示波器 / C+J 电平与相位 / D 利萨如（**唯一带状态**：余辉） |
| `VizWindow(±xaml)` | 附件窗口：读侧所有权、几何持久化、放置落地、空格键、拖放、**F12 统计叠层** |
| `VizSurfaceHost` | **五块区域的布局**（两个宿主共用：附件窗口 + 主窗口内嵌） |
| `VizRenderers` | 四块渲染器实例（**两处宿主共享同一份**，尤其 D 的余辉） |
| `VizHost` | `FreeHost` / `WindowHost`（宿主几何 + **所在显示器工作区**） |
| `VizPlacementLogic` | 放置判定与窗口动作（**纯函数**，自检直接驱动） |
| `VizWindowSizing` | `WM_SIZING` 钩子：贴附下**只允许拖右边缘** |
| `VizCommandLine` | `--viz` / `--viz-selftest` 分流 |
| `VizCover` | **封面解析**（M7）：`<id>`/`<id>_alt` → 程序集里的图；**副版存在才用、否则回退主版** |

## 四、自检覆盖到什么 / 覆盖不到什么

**覆盖**：常量与缓冲形状、FFT/RMS/相关度、四个渲染器的**离屏像素**、D 的风险状态机、
布局比例（离屏 `Measure/Arrange`）、每帧分配、淡出/归零语义、分接节点、节拍退订、延迟取窗、
编码路由、窗口构造、放置判定与动作、`WM_SIZING` 折算、设置往返。

**覆盖不到（只能人工验）**：

- ⚠️ **主窗口布局**：构造 `MainWindow` 会连带建引擎、加载播放列表、起定时器 —— 自检刻意不碰它。
- ⚠️ **任何需要真窗口的行为**：自检里 `Show()` 一个窗口会把进程带下去（`ShutdownMode=OnLastWindowClose`），
  所以「窗口最后可见吗」这类断言在自检里**恒为假**，一律改成断言「**决定**」或「**渲染结果**」。

## 五、没做的（都不是缺口，是登记在案）

| 项 | 说明 |
| --- | --- |
| 附件窗口的 `ShowInTaskbar` | 方案 §6 写「隔离期要靠它找窗口，**接入期再关**」—— 还没关（自由模式下其实该留着） |
| **空格暂停键** | 有意留着（**不是欠账**），接入后已惰性 —— 见下 |

**关于空格键**：M4 加它是为了在隔离期验证「暂停 → 衰减」这条语义（那时调试声源没有任何播放控件）。
接入后 handler 第一句就是 `_debugFeed is null` 直接返回，而接入期读侧是引擎的 `VizTap`，
所以按空格**什么都不做** —— 「窗口成了第二个暂停入口」这个顾虑已经被守卫消掉了。
留着是因为 **`--viz` 诊断入口下还用得上**（不起播放器就能看淡出语义）。
⚠️ 主窗口**没有**空格绑定（`Window_PreviewKeyDown` 只处理 `MediaPlayPause` 等媒体键），
所以不存在被它遮挡的快捷键，也没有两个真相源。
| 帧距**峰** 25~37ms | 与 D 层数无关，疑为 GC / 外部调度。见掉帧档「不追的账」 |
| `--viz` 入口 | 保留作诊断入口（不启动主窗口、不走引擎） |

## 六、两条值得记住的教训（散见各文档，这里集中）

1. **「文档里写了」≠「代码里做了」**（build-46 §五）：过渡性决定必须在**代码里**留 TODO 常量/字段，
   不能只写在文档里 —— 文档没有编译器盯着。
2. **量「录绘制指令」≠ 量「把它画出来」**（掉帧档）：UI 线程的耗时读数好看，不代表帧能出来；
   **要量帧距**。这条直接决定了那次掉帧花了三轮才定位。
