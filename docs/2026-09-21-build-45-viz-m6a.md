## 二、真分接节点：`VizTap`

插在**音量之后、16bit 转换之前**（`PlayerEngine.cs:86`，正是方案 §10 说的那 1 行）：

```csharp
player.Init(new SampleToWaveProvider16(_vizTap));   // 原来是 _volume
```

于是「取样点在音量后」落地了：**所见即所听，音量拉到 0 画面跟着归零**（§8.1#6）。

### 三条音频线程纪律

1. **零分配** —— `Read` 里不 new 任何东西（环是构造期预分配的）。
2. **无锁** —— 单写单读 + `Volatile` 写指针（见 `VizRing`）。
3. **返回值原样透传** —— 绝不靠返回值表达"没在播"：返回 0 会让 `WasapiPlayer`
   判定流结束并触发 `PlaybackStopped`。

### 🔑 「活动性即播放状态」

`IsPlaying` 不用引擎回写一个布尔，而是**看音频线程最近 250ms 有没有在拉数据**：

```csharp
public bool IsPlaying => !_disposed && Environment.TickCount64 - Volatile.Read(ref _lastPullMs) < ActiveWindowMs;
```

好处是**没有第二个真相源**：暂停 → 播放线程不再拉 → 窗口过后自动 false → 走「淡影」；
切设备那几毫秒停顿越不出窗口，所以不闪；释放后恒 false → 走「归零」。

### ⚠️ 半帧取整

```csharp
int frames = read / _channels;    // 最多丢掉凑不满一帧的尾部样本
```

上游交出奇数个浮点样本时，**只丢那个尾巴**；写进去的话之后所有样本的声道会全部错位。
自检直接拿 101 个样本喂进去验这一条。

### ⚠️ 它不随输出设备切换重建

`BuildOutput()` 在切设备时会被再调一次，但 `_vizTap` 是**引擎长期持有的字段** ——
重建会让环里攒的数据与可视化的订阅方一起断掉（每切一次设备画面清空一次）。

## 四、入口两处（方案 §十一 的落地）

### 4.1 设置页新增「可视化」标签页

`SettingsWindow.xaml` 原来是 4 页（路径 / 播放参数 / 导出 / 外观）→ 现在是 **5 页**（新页是 index 4）。
放的全是**已存在但一直没有 UI 的字段**，顺带兑现了方案 §五 那句「面板开关，本次不做 UI」：

| 控件 | 字段 |
| --- | --- |
| 启用可视化 | `Enabled`（**本轮新增**） |
| 跟随主窗口（贴右侧、等高） | `Attached` |
| 与听觉对齐（毫秒） | `LatencyOffsetMs`（上限复用命令行那一份，避免同一数值两处漂移） |
| A / B / C+J / D / 封面 | `ShowA` / `ShowB` / `ShowC` / `ShowD` / `ShowCover` |

⚠️ **需要新增字段 `VizSettings.Enabled`**：方案 §五 的字段表里没有总开关，
`Attached` 是「贴附 vs 自由」不是「启用」—— 两者不能合并。
连带把 `CheckSettingsRoundTrip` 的**逐字段**断言也扩了（含落盘探针），否则新字段漏进 JSON 也没人发现。

### 4.2 主窗口快速开关

放在 `PlaylistSummary`（「N 首」）**左边** —— 用户 2026-09-20 定的位置。
实现是**塞进 col 3 那个弹性列并右对齐**，不新增列：这一行是既有布局，
新增列要顺移后面所有 `Grid.Column`，而右对齐在观感上等价。

**两处入口一个值**（`AppSettings.Viz.Enabled`）。两个坑：

1. **`IsChecked = x` 也会触发 Checked/Unchecked** → 不挡一下就会「同步状态 → 触发回调 → 又去开关窗口」，
   方向还是反的。用 `_vizToggleSyncing` 挡 ✓。
2. **设置窗口关掉后主窗口必须重读** → 挂在既有的 `ApplySettingsSideEffects` 上
   （它在点「应用」和关窗后各跑一次，全部幂等）✓。

### 4.3 面板开关真的生效

做法是「有渲染器就画、没有就是空白」（`VizPanel.Renderer` 为 null 时什么都不画）——
**不动 XAML 可见性，因此不牵动 2.3:1 / 7:3 那套分区比例**。
⚠️ 这是刻意的：关掉一块只是不画、不重排布局，否则每开关一次整块画面都会跳一下。
封面不是 `VizPanel`，那个才切可见性（`CoverCell`）。

## 五、宿主与窗口所有权

### `WindowHost`：工作区必须取**宿主所在那块**显示器

```csharp
MonitorFromWindow + GetMonitorInfo → 物理像素 ÷ 缩放比 → DIP
```

⚠️ **不能用 `SystemParameters.WorkArea`** —— 那是**主**显示器的。
主窗口在副屏时，拿它去算「贴右侧」会把窗口定位到主屏边缘去。

### `ApplyVizEnabled`：幂等 + 关窗顺序

- **已开着就只刷新**，不重建窗口（重建会把画面历史、D 的余辉、贴附几何全丢掉）。
- ⚠️ **关掉时必须先摘宿主再关窗**：宿主订阅还挂着的话，主窗口下一次移动/缩放/最大化
  还会推到那个已关闭的窗口上，把它重新 `Show` 出来 —— 表现为「关了又自己冒出来」。

### `VizWindow` 的读侧所有权

新增 ctor 参数 `IVizFeed? feed`（接入期注入引擎分接节点），并把两个引用分开：

| 字段 | 含义 |
| --- | --- |
| `_feed` | 当前读侧（自带调试声源 **或** 引擎注入的） |
| `_debugFeed` | **只有自己建的**那个，可能为 null |

暂停（空格）/ 播完归零 / 拖放换源 / 释放，**一律只对 `_debugFeed` 做** ——
引擎那份归引擎管，窗口去动它就是把所有权搞混了（`TearDownSource` 里也只 Dispose 自己那个）。
