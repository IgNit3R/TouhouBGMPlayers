## 一、四处问题的根因与修法

| # | 现象 | 根因 | 修法 |
| --- | --- | --- | --- |
| **1** | 勾选「可视化」后窗口出现但**不附着**；在设置里打开「跟随主窗口」也**要关掉窗口重开才生效** | ① `Attached` 默认 **false**；② **贴附只在「建窗口」那一刻读一次** —— 运行中改设置只走到 `RefreshPlacement()`，而它**在 `Host` 为 null 时是空操作**，于是宿主**永远不会被建** | ① 默认改 **true**（方案的窗口形态本来就是「贴右侧、等高」，自由是退路）；② 新增 `SyncVizAttachment()`：**贴附是一份状态，不是一次性动作**，已开着的路径上也要让它收敛 |
| **2a** | **未播放时可视化区域一片空白**（只剩空框） | **面板没有「帧」就什么都不画**；而未播放时 `IsPlaying=false` → 节拍不起搏（就算起搏也会立刻自我退订）→ **一帧都没渲染过** | 新增 `RenderOnce()`（幂等、不依赖播放状态），在 `Loaded`、**建窗后**、面板开关变化后各调一次 |
| **2b** | **开始播放后画面也不动** | **没有任何人在「开始播放」时起搏** —— 引擎**没有播放状态事件** | 借主窗口既有的 **100ms `Tick`** 调 `RefreshFeedState()`（只在播时起搏；停搏仍归 `VizPump` 自退订）。代价：恢复播放的画面**最多晚 100ms** 起来 |
| **3** | 勾选要**按钮式** | — | 新增 `ToggleSwitch` 样式（外观与 `Button` 同源 + 选中态用主题 `Accent` 填底），控件换成 `ToggleButton` |
| **4** | 设置菜单里**没有可视化**，得先点开别的标签页才看得到 | 上一轮我刻意没加菜单项（怕成第三个真相源） | 加「设置 → **可视化…**」→ `OpenSettings(4)` |

### ⚠️ 第 3 项的坑：样式**必须带 `x:Key`**

隐式 `TargetType="ToggleButton"` 样式会把 `Padding` / `Background` 这些 setter
**也套到 `ComboBox` 模板内部那个 `ToggleButton`** 上 —— 它只显式覆盖了 `Template`，
没覆盖 `Padding`，于是**每个下拉框的箭头按钮都会被撑成 12,4 的内边距**。
所以做成 `x:Key="ToggleSwitch"`，只给这一个控件用。

### 第 1 项的教训

> 贴附/内嵌这种「由设置驱动、由宿主决定」的状态，**必须写成收敛（idempotent）的同步**，
> 不能写成「建对象时读一次」。否则运行中改设置就得靠重建对象才生效 ——
> 而看到的现象是「设置不起作用」，查起来会先怀疑设置读写，方向就偏了。

## 二、我自己发现的同源缺口（一并修）

**「切曲 / 播完 → 归零」（方案 §2）在引擎这条链上没人触发。**

隔离期靠调试声源的 `HasEnded` 自己判断；引擎的读侧只能表达「还在出声吗」，
**分不出暂停与播完**（两者都不再出声）—— 所以必须由**知道内情的一方**说：

- 新增 `VizWindow.NotifyTerminated()`（归零 + 立刻重画一帧）。
- 调用点：`PlayTrack` 开头（换曲 = 终止语义，放在最前面，后面无论走哪条分支都算「上一首结束了」）+
  主窗口 tick 里「播完了但后面没有曲子」那一支。

不补的话现象是：切曲后画面停在上一首的**淡影**上，而不是清干净。

`VizSettings 序列化往返` 里补了**默认值**断言（默认错了用户第一次点开就是错的观感）：

```
内存往返=是；默认值（贴附/关/五块全开/延迟100）=是；落盘往返 ok；当前值 426×503 延迟 100ms
```

锁住的默认：`Attached=true` / `Enabled=false` / 五块面板全开 / 延迟 100ms / 宽 560 / 最大化内嵌 true。

## 四、待用户复验（自检覆盖不到的部分）

1. 主窗口勾「可视化」→ 窗口应出现在**右侧、顶对齐、等高**（现在默认就贴附）。
2. **未播放时**可视化窗口里应该有底槽、刻度、L/R 标签、J 的槽与刻度（静止态）——
   不是空白。
3. 点播放 → 五块开始动（最多晚 100ms）。
4. 切下一首 → 画面**先清干净**再重新开始（不是留上一首的淡影）。
5. 设置里改「跟随主窗口」→ 关掉设置窗口 → **立刻**生效，不必重开可视化窗口。
6. 设置菜单里应看到「可视化…」，点它直接定位到该标签页。
7. 勾选框现在是**按钮式**（选中时 Accent 蓝底白字）。

## 五、第六处：主窗口最大化时**整块可视化凭空消失**

用户复验第二张截图暴露的。**这是我上一轮文档与实现不一致造成的**：

- `docs/2026-09-21-build-45-viz-m6a.md` 里写着「本轮 `Decide` 一律传 `embedWhenMaximized: false`」……
- **但代码里没那么写** —— `VizWindow.xaml.cs:340` 直接读 `AppSettings.Current.Viz.EmbedWhenMaximized`，
  而它**默认 true**。

于是最大化时：`Decide` → `AttachedEmbedded` → `ShowAttachedWindow=false` → **附件窗口 `Hide()`**，
而主窗口里**还没有内嵌画面**（那是 M6b 的活）→ **整块可视化消失**，
用户看到的就是「勾还亮着、但什么都没有」。

**修法**（1 行 + 注释）：

```csharp
/// ⚠️ M6a 阶段恒为 false：内嵌宿主还没做，传 true 就会"隐藏了却没人接手显示"。
/// M6b 落地时改回 AppSettings.Current.Viz.EmbedWhenMaximized（字段早就在了）。
private static bool EmbedWhenMaximized => false;
```

这样最大化走方案 §3.6 判定表里「**Maximized 且非 embed → 退化为贴右侧**」那一支：
窗口仍在，贴到工作区右侧、宽 360、全高（会压住最大化窗口的右边缘）。

⚠️ **这条没法进自检**：`ApplyPlacement` 在 `Show` 分支会调 `Window.Show()`，
而自检里 `Show()` 一个窗口会把进程带下去（`ShutdownMode=OnLastWindowClose`）——
所以只能靠人工验收（见 §四 之外的那一条：**最大化 → 可视化窗口应仍在，贴在屏幕右侧**）。

### 教训

> **「文档里写了」不等于「代码里做了」。** 本轮我先把意图写进了构建记录，再去实现，
> 中间把这一条漏掉了 —— 而构建记录读起来像已完成。以后凡是「本轮先这样、M6b 再改回来」
> 这类**过渡性决定**，必须在代码里留一个显式的 TODO 常量/字段，
